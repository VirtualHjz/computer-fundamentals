# Tests

## Test 1 - 从首页进入目录再打开独立知识页 [sanity]
Viewport: desktop
Covers: 首页入口, Hash 子页面路由, 结构化知识目录, 独立知识页
Description: 验证首页只承担入口职责，用户能通过目录进入一个独立 URL 的知识页面。

Steps:
1. 在首页点击“打开结构化目录”
2. 在“信息与机器”分组点击“CPU、指令与时钟”
3. 查看页面地址与知识页标题

Expected: 地址 hash 为“#/knowledge/cpu”，页面显示“CPU、指令与时钟”，并可见独立的本页目录与“先把它看见”可视化区域。

## Test 2 - 操作知识页可视化并继续前后知识
Viewport: desktop
Covers: 每知识点独立可视化, 机制讲解, 知识页前后导航
Description: 验证知识页不是静态定义，而是包含可操作模型并能沿推荐顺序继续学习。

Steps:
1. 打开“#/knowledge/bits-bytes”
2. 拖动“调整十进制数值”滑块并观察 8 个 bit 与等式变化
3. 点击页面底部“下一个”进入 CPU 页面

Expected: bit 可视化会随滑块更新；底部导航进入“CPU、指令与时钟”独立页面。

## Test 3 - 搜索目录并处理不存在的知识路由
Viewport: desktop
Covers: 目录搜索, 空状态 guardrail, 不存在路由 guardrail
Description: 验证目录能按知识/术语筛选，并对错误子页面提供明确返回路径。

Steps:
1. 打开“#/catalog”，搜索“TLS”
2. 确认只保留与 HTTP/TLS 相关的知识卡片
3. 将地址改为“#/knowledge/not-a-real-node”

Expected: 搜索可定位“HTTP、TLS 与一次请求”；不存在路由显示“这个知识页还不存在”并提供“回到知识目录”入口。

## Test 4 - 手机端完成首页到知识页的完整路径
Viewport: mobile
Covers: 移动端首页, 移动端目录, 移动端知识页目录, 响应式可视化
Description: 验证窄屏下三层信息架构和核心学习交互仍完整可用。

Steps:
1. 从首页进入知识目录
2. 打开“Token、Embedding 与表示”
3. 展开“本页目录”，点击“1. 先看可视化”，再点击向量示意中的“猫”和“汽车”

Expected: 页面保持单列可读；本页目录可展开；Embedding 可视化可以切换选中的概念且不产生横向溢出。
